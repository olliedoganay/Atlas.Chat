# Atlas Chat v1.2.0

Release date: 2026-07-23

Atlas Chat 1.2 modernizes first-run setup and model management while tightening the local trust boundary, profile storage, Docker runner, dependency supply chain, and release verification.

## Provider setup and model downloads

- **Settings > Connections** now configures Ollama, LM Studio, llama.cpp server, vLLM, LocalAI, or a generic local OpenAI-compatible endpoint without editing `.env`.
- Saving a provider or API URL restarts the managed backend so the selected runtime is applied consistently to chat and discovery.
- Optional provider API keys are protected with operating-system secret facilities before they are persisted. The settings API exposes only key status, and Atlas refuses to save a key when secure OS protection is unavailable.
- Saved Connection settings take precedence over equivalent environment defaults. The existing `ATLAS_CHAT_PROVIDER`, `ATLAS_CHAT_BASE_URL`, and `ATLAS_CHAT_API_KEY` controls remain available for direct backend runs and automation.
- Discovery now starts real Ollama model pulls, streams status and byte progress, supports cancellation, offers retry after failure, and refreshes the installed catalog after completion.
- Atlas deduplicates repeated requests for the same model and allows one managed pull at a time. Copyable `ollama pull ...` commands remain available as a manual fallback.

## Security and local data

- Profile and thread namespace keys now use a versioned, collision-free encoding. Recognized legacy keys are migrated without discarding existing profile or thread records.
- Locked profiles retain ownership checks across chat, memory, search, branch, reset, and runner-adjacent operations. Cached profile keys are overwritten when a profile locks or the backend closes.
- The CLI now unlocks protected profiles through a hidden prompt, `ATLAS_PROFILE_PASSWORD`, or the explicit `--password-stdin` option instead of requiring secrets in command arguments.
- Plaintext SQLite and Qdrant migrations are staged, verified, and swapped atomically when SQLCipher and application key protection are available. Restricted recovery backups are retained, and failed migrations restore or preserve the original data.
- Encryption status is reported as active only when both SQLCipher and secure application key protection are available.
- Mem0 telemetry is disabled before the memory runtime loads, preventing third-party usage events and shared telemetry storage outside `ATLAS_DATA_DIR`.
- Backend request models now enforce identifier, prompt, model, attachment, memory, and code-size budgets. Provider URLs reject embedded credentials, query strings, and fragments.
- Managed API startup keeps its loopback-only boundary, uses constant-time instance-token comparison, performs authenticated readiness checks, and terminates a backend that never becomes ready.
- The Tauri shell requests an authenticated runner shutdown before terminating the backend, allowing owned Docker containers to be cleaned up first.

## Code runner hardening

- `ATLAS_RUNNER_NETWORK=none` is the default and never silently upgrades to outbound networking.
- When a GUI or web preview needs a published loopback port under `none`, Atlas uses an internal Docker network with no external route. `bridge` is the only mode that grants outbound access.
- Dependency-aware snippets show a network warning when package installation cannot proceed offline. Operators must explicitly select `bridge` for package resolution or networked code.
- Runner images use fully qualified, versioned names. Containers drop capabilities, enable `no-new-privileges`, bind submitted source read-only, and use a read-only root filesystem plus an unprivileged user where the workload permits.
- CPU, memory, PID, open-file, output, file-size, timeout, history, subscriber-queue, and concurrent-run bounds prevent unbounded local resource use.
- Containers carry Atlas ownership labels and are removed on stop, failed startup, stale-owner cleanup, and backend shutdown.

## Interface, accessibility, and performance

- First-run setup is now a progressive profile/provider/model/first-prompt flow with direct links to Connections and Discovery plus manual setup details when needed.
- Empty workspaces include starter prompts for planning, writing, and code review.
- First-run and global-search surfaces use focus-trapped dialog primitives with focus restoration, semantic titles/descriptions, keyboard result navigation, explicit control labels, and live status announcements.
- The desktop shell has a 900 px minimum width and responsive compact layouts for split-screen and shorter-window use. Workspace headers, thinking panels, Settings navigation, search, and onboarding reflow at smaller breakpoints.
- The visual hierarchy now uses a consistent 14 px base, denser controls, clearer focus treatment, and a consolidated responsive layer.
- Discovery, Advanced, Settings, the code runner, Markdown rendering, and syntax highlighting load in separate chunks where practical.
- Font imports now use only the required Latin subsets. Together with route and content splitting, the main production JavaScript chunk decreased from roughly 503 KB to 446 KB in the final release build.
- Streamed token events are batched for durable run storage while remaining immediately visible to live readers, reducing per-token disk writes without changing replay behavior.

## Dependencies, CI, and packaging

- Runtime and tooling dependencies were refreshed and audited across Python, npm, and Cargo.
- The packaged backend now includes only Atlas's Ollama/Qdrant memory adapters, excluding unused cloud-provider and dependency test modules.
- `requirements.lock` is a universal, hash-locked Python environment for reproducible Linux, Windows, and macOS installs. Install it with:

  ```bash
  python -m pip install --require-hashes -r requirements.lock
  python -m pip install --no-deps -e .
  ```

- CI verifies the backend, frontend, and Rust desktop shell on Ubuntu, Windows, and macOS. Linux additionally gates Ruff, rustfmt, and Clippy.
- Dedicated security checks run Python and npm dependency audits, CodeQL covers Python and JavaScript/TypeScript, and Dependabot tracks Python, npm, Cargo, and GitHub Actions updates.
- Release jobs fail when an expected installer is missing and publish SHA-256 checksum files beside Windows MSI, Linux `.deb`/`.rpm`/AppImage, and macOS x64/arm64 DMG assets.

## Upgrade notes

- Existing Atlas-managed data is preserved. Atlas migrates recognized legacy namespace keys automatically; encrypted-store migrations keep restricted recovery copies under the Atlas data directory.
- A provider saved under **Settings > Connections** overrides provider values in `.env`. Update or clear the saved Connection setting if an environment-only change appears not to take effect.
- Runner users who previously depended on automatic package downloads must explicitly set `ATLAS_RUNNER_NETWORK=bridge`. Keep the default `none` mode for offline snippets.
- Source installs should move from `requirements.txt` to the checked-in `requirements.lock` command above.
- Packaged Intel and Apple Silicon builds now require macOS 14 or newer, matching the release sidecar's native dependency floor.
- macOS community builds remain unsigned and unnotarized, so the first launch may require manual approval in Finder.
